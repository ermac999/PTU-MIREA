## Вычитание через сложение

В дополнительном коде вычитание не нужно:

{A − B = A + (−B)}

23 + (−9), 8 бит:\
00010111 + 11110111 = **1** 00001110

Девятый бит не помещается в 8-битную ячейку — отбрасываем. Остаётся 00001110 = **14**.

## Переполнение

Результат вышел за диапазон. 8 бит: −128 … 127.

100 + 50 = 150 > 127 → в ячейке окажется 10010110 = **−106** (150 − 256).

**Признак:** сложили два числа одного знака, а знак результата другой. У чисел разных знаков переполнения не бывает.

Перенос за разрядную сетку ≠ переполнение: в 23 + (−9) перенос есть, а ответ верный.

## Вещественные числа

Хранятся как **знак, порядок и мантисса**: x = ± m · 2ᵖ.

Это даёт огромный диапазон, но приводит к **ошибкам округления** и конечной точности.

Стандарт **IEEE 754**:

- float — 32 бита: 1 + 8 + 23
- double — 64 бита: 1 + 11 + 52 (это float в Python)

## Нормализованная форма

Дробную часть переводим умножением на 2:

0,75·2 = 1,5 → 1\
0,5·2 = 1,0 → 1 → 0,11₂

12,75 = 1100,11₂ = **1,10011₂ · 2³** (запятую сдвинули на 3 влево).

```
import math
print(math.frexp(12.75))  # (0.796875, 4)
```

Python берёт мантиссу из [0,5; 1): 12,75 = 0,796875 · 2⁴. Это то же число, просто другая договорённость.

## Почему 0,1 + 0,2 ≠ 0,3

0,1₁₀ = 0,0001100110011…₂ — бесконечная дробь. В память попадает округлённое значение.

Точно хранятся только дроби вида k/2ᵐ: 0,5; 0,25; 0,75; 0,125…

```
print(0.1 + 0.2)         # 0.30000000000000004
print(0.1 + 0.2 == 0.3)  # False
```

Сравнивай так: **math.isclose(a, b)** или abs(a − b) < 1e-9.

## Про sum() в новом Python

> В тетради sum([0.1 for _ in range(10)]) даёт 0.9999999999999999. В Python **3.12+** sum() складывает float точнее и может вывести **1.0**.
> Если у тебя в блокноте вышло 1.0 — дело в версии, а не в ошибке. Цикл всё равно покажет накопление ошибки:

```
s = 0.0
for _ in range(10):
    s += 0.1
print(s)  # 0.9999999999999999
```
